# I2: Multi-Input Ask in Drift

This document describes the updated `ask` system for chained and nested input prompts.

The original input implementation only supported a single prompt/target pair. The updated system supports repeated prompt-target pairs in the same statement and also allows the prompt string itself to contain an implicit target pattern like `{@name}`.

## 1. Supported forms

The current `ask` system supports all of these patterns:

```drift
ask "Enter your age: " @age
```

```drift
var age = ask "Enter your age: "
```

```drift
ask "Enter your age: {@age} "
```

and now also:

```drift
ask "First name: " @first "Last name: " @last
```

```drift
ask "Name: " @name "Age: " @age "City: " @city
```

```drift
ask "Nickname: {@nick} "
```

```drift
ask "User: " @user "Role: {@role} "
```

These can be combined in a single statement so that multiple inputs are read one after another in a single flow.

---

## 2. Chained input behavior

The parser now builds a list of prompt/target items for a single `ask` statement.

Example:

```drift
ask "First name: " @first "Last name: " @last
```

This behavior is processed as:

1. print `First name: `
2. read input and store it in `first`
3. print `Last name: `
4. read input and store it in `last`

This means one `ask` statement can collect several values without needing multiple independent statements.

---

## 3. Prompt template nesting

The input system also supports nested prompt formats where the prompt itself contains an implicit target marker:

```drift
ask "User nick: {@nick} "
```

This works by detecting the pattern `{@name}` inside the prompt string, removing it from the visible prompt, and using `name` as the target variable.

So the user sees:

```text
User nick: 
```

and the read value is stored in `nick`.

This can also be mixed with the explicit style:

```drift
ask "Name: " @name "Nick: {@nick} "
```

This allows the language to combine the three core forms inside the same `ask` statement.

---

## 4. Mixed style support

The implementation supports all current input styles together inside one chain:

```drift
ask "Name: " @name "Age: " @age "City: {@city} "
```

This is processed as:

- prompt `Name: ` and store to `name`
- prompt `Age: ` and store to `age`
- prompt `City: ` and store to `city`

The prompt text can include both explicit `@var` targets and implicit `{@var}` targets at the same time.

---

## 5. Variable declaration interaction

The `var = ask ...` form still works, and it also supports prompt strings with implicit targets or chained values as long as the syntax remains valid.

Example:

```drift
var age = ask "How old are you? "
```

This reads input and assigns the result to the newly created `age` variable.

---

## 6. Parsing model

The parser now treats `ask` as a sequence of input items rather than a single item only.

Internally, it builds an array of input records, each containing:

- `prompt`
- `target_name`
- `has_prompt`
- `has_target`

Then the interpreter executes each item in order.

This allows a single source line to become multiple reads while remaining easy to extend later.

---

## 7. Example programs

### Example 1: multiple explicit targets

```drift
ask "First: " @first "Last: " @last
say "Hello {first} {last}!"
```

### Example 2: mixed prompt formats

```drift
ask "Name: " @name "City: {@city} "
say "{name} lives in {city}"
```

### Example 3: declaration-based input

```drift
var age = ask "Age: "
say "You are {age}"
```

---

## 8. Current limitations

This beta version still keeps the system intentionally simple:

- reads one line at a time
- no advanced validation yet
- no arrays or structured input parsing
- no nested function calls inside `ask`

But the grammar now clearly supports repeated and mixed prompt styles in a single statement, which is the required foundation for multi-step interactive input.

---

## 9. Summary

The `ask` system has been expanded from a single-read operation to a chained, multi-input operation:

- explicit `@var` targets are supported
- implicit `{@var}` targets are supported
- multiple prompt-target pairs can appear in one statement
- mixed forms can be combined inside the same `ask`

This makes the interactive input system much more usable while preserving the small and readable design of the language.
