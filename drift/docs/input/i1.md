# I1: Input System in Drift

This document describes the input system currently implemented in Drift, including the `ask` keyword and the supported input forms so far.

The goal of this milestone is to add a basic interactive input flow to the language while keeping it simple, deterministic, and consistent with the existing parser and interpreter model.

## 1. Overview

The language now supports the following interaction patterns:

```drift
ask "Enter your age: " @age
```

```drift
var age = ask "Enter your age: "
```

```drift
ask "Enter your age: {@age} "
```

These forms let the interpreter read a line from standard input, parse the value, and store it in a variable.

---

## 2. Supported input forms

### Form 1: Prompt + target variable

```drift
ask "Enter age: " @age
```

Behavior:

- prints the prompt text to stdout
- reads one line from stdin
- converts the input into a Drift value
- stores the result in the variable `age`

Example:

```drift
ask "Enter age: " @age
say "Age is {age}"
```

If the user enters:

```text
20
```

Then output becomes:

```text
Enter age: Age is 20
```

---

### Form 2: Assignment from `ask`

```drift
var age = ask "Enter your age: "
```

Behavior:

- prints the prompt text
- reads one line from stdin
- stores the result in the variable `age`
- the variable is automatically created and initialized with the parsed input value

Example:

```drift
var age = ask "Enter your age: "
say "Age is {age}"
```

If the user enters:

```text
30
```

Then this prints:

```text
Enter your age: Age is 30
```

---

### Form 3: Prompt template with implicit input target

```drift
ask "Enter your age: {@age} "
```

Behavior:

- detects `{@name}` inside the prompt string
- strips that target marker from the visible prompt text
- reads input from stdin
- stores it in the variable `age`

This is useful when you want the input prompt to look like a single sentence while the target variable is still clearly visible in the code.

Example:

```drift
var age
ask "Enter your age: {@age} "
say "Age is {age}"
```

Example run:

```text
Enter your age: 25
Age is 25
```

The target expression is not treated as a standard interpolation string; it is explicitly recognized by the parser and converted into an input target.

---

## 3. Value parsing rules

The input parser reads the raw text from stdin and converts it into a Drift value.

### Supported parsing behavior

#### Integer

```text
20
```

becomes:

```text
VALUE_INTEGER
```

#### Float

```text
3.14
```

becomes:

```text
VALUE_FLOAT
```

#### Boolean

```text
true
false
```

becomes:

```text
VALUE_BOOLEAN
```

#### Null

```text
null
```

becomes:

```text
VALUE_NULL
```

#### Infinity

```text
inf
```

becomes:

```text
VALUE_INFINITY
```

#### String fallback

Anything else is treated as a string literal value, for example:

```text
Israfil
```

becomes:

```text
VALUE_STRING
```

This keeps the system flexible while still allowing simple interactive prompts to work for common use cases.

---

## 4. Default initialization behavior

The language also supports declarations without an initial value:

```drift
var age
```

This is treated as a valid declaration and initializes the variable to `NULL` by default.

This was added to match the language expectation that variables are safe to declare before they are assigned.

Example:

```drift
var age
say age
```

The variable is created but contains `null` until a value is assigned or read from input.

## 5. Lexer implementation

The lexer was extended to recognize the new input keyword and target marker.

### New token types

The token system now includes:

- `TOKEN_ASK`
- `TOKEN_AT`

These are added in `include/drift/token.h`.

### Lexer changes

The lexer behavior was updated in `lexer/lexer.c` so that:

- the word `ask` is recognized as a keyword
- the `@` symbol is recognized as a token
- input prompts are still read as normal strings when they appear in quotes

This preserves the existing lexical model without disturbing the current `say` and `var` syntax.

---

## 6. Parser implementation

The parser in `parser/parser.c` now accepts three main forms of the `ask` construct:

1. `ask "prompt" @var`
2. `var x = ask "prompt"`
3. `ask "prompt with {@var}"`

The parser stores the information in a new `InputStatement` struct and also keeps compatibility with the `Statement` enum system.

### New statement type

The statement model introduces:

```c
STATEMENT_INPUT
```

This is defined in `include/drift/statement.h`.

The AST includes relevant fields such as:

- `prompt`
- `target_name`
- `has_prompt`
- `has_target`

This keeps the input operation separate from regular print or variable declaration statements.

---

## 7. Interpreter implementation

The actual runtime behavior lives in:

- `include/drift/input.h`
- `interpreter/input.c`
- `interpreter/intptr.c`

### `drift_read_line_from_stdin()`

This reads a line from the terminal using `fgets()`, trims the trailing newline, and returns the text to the caller.

### `drift_parse_input_value()`

This function converts the raw input text into a Drift value based on a few simple rules:

- `true` and `false` become booleans
- `null` becomes a null value
- `inf` becomes infinity
- integers and floats are converted with `strtol()` and `strtod()`
- everything else becomes a string

### `interpreter_execute()`

When the parser emits a `STATEMENT_INPUT`, the interpreter:

- resolves the prompt string if one exists
- reads input from stdin
- parses it into a value
- writes it to the target variable or to the declared variable

This is how the language handles all three input forms.

## 10. Notes and limitations

This input system is intentionally lightweight and matches the current stage of the language.

Current limitations:

- only line-based input is supported
- no advanced parsing or custom type syntax yet
- no validation beyond basic automatic value conversion
- no multi-value input or expression parsing

The system is designed as a foundation for later improvements such as:

- richer prompt formatting
- input validation
- `ask` in conditionals and loops
- arrays or structured input parsing

---

## 11. Summary

The current input system provides a simple interactive reading model for Drift:

- `ask` reads from stdin
- prompt text is optional
- variables can receive input directly with `@name`
- variables can be assigned from `ask` expressions
- prompt templates can include `{@var}` as an implicit target
- undeclared variables default to `NULL`

This makes the language more interactive while staying consistent with the rest of the interpreter architecture.
