# V1: Variable Declaration in Drift

This document describes the variable declaration system in Drift v0.2.

The current milestone introduces the ability to declare variables with automatic type inference.

## 1. Declaration syntax

The language supports this syntax:

```drift
var name = "Israfil"
var age = 20
var pi = 3.1416
var online = true
```

Rules:

- the keyword is `var`
- a variable must have a name
- the name must be followed by `=`
- the right-hand side must be a literal only
- no expressions are supported yet
- no arithmetic is supported yet
- no reassignment is supported yet

## 2. Supported literal types

### Integer

```drift
var age = 20
```

Example output:

```text
20
```

### Float

```drift
var pi = 3.1416
```

Example output:

```text
3.1416
```

### String

```drift
var name = "Israfil"
```

Example output:

```text
Israfil
```

### Boolean

```drift
var online = true
```

Example output:

```text
true
```

## 3. Variable printing

Once a variable is declared, it can be printed with `say`:

```drift
var name = "Israfil"
say name
```

Output:

```text
Israfil
```

This works for all supported literal types:

```drift
var age = 20
say age

var pi = 3.1416
say pi

var online = true
say online
```

## 4. Supported declaration methods

There are several valid declaration forms in the current language, all using the same core rule: `var <identifier> = <literal>`.

### Method 1: Integer variable

```drift
var age = 20
```

This creates an integer value in the environment.

### Method 2: Float variable

```drift
var pi = 3.1416
```

This creates a floating-point value in the environment.

### Method 3: String variable

```drift
var name = "Israfil"
```

This creates a string value in the environment.

### Method 4: Boolean variable

```drift
var online = true
```

This creates a boolean value in the environment.

## 5. Identifier rules

Identifiers must follow these rules:

- must begin with a letter or `_`
- may contain letters, digits, or `_`
- cannot begin with a digit
- cannot contain spaces
- cannot contain `-`

Examples:

Valid:

```drift
age
student1
_name
playerScore
```

Invalid:

```drift
123abc
my-name
first name
```

## 6. Not allowed yet

This version intentionally forbids expression-based declarations. These are syntax errors:

```drift
var x = 5 + 10
var x = y
var x = func()
var x = []
var x = {}
```

Only literal values are allowed on the right side.

## 7. Error handling for declarations

### Missing variable name

```drift
var
```

Error:

```text
Syntax Error: Expected variable identifier after 'var'.
```

### Missing assignment

```drift
var age
```

Error:

```text
Syntax Error: Expected '=' after variable name.
```

### Missing value after equals

```drift
var age =
```

Error:

```text
Syntax Error: Expected value after '='.
```

### Invalid identifier

```drift
var 123abc = 5
```

Error:

```text
Syntax Error: Invalid identifier '123abc'.
```

### Undefined variable when printing

```drift
say age
```

If `age` was never declared:

```text
Runtime Error: Undefined variable 'age'.
```

### Duplicate declaration

```drift
var age = 20
var age = 50
```

Error:

```text
Runtime Error: Variable 'age' is already declared.
```

## 8. Environment model

The runtime keeps a variable environment that stores values by name.

Each variable is saved in an environment table using:

- variable name
- value type
- value data

This allows the interpreter to look up variables when the user prints them later.

## 9. Current architecture role

The variable system follows the same interpreter structure:

- Lexer reads `var`, identifiers, `=`, and literals
- Parser builds a `VariableDeclaration` AST node
- Interpreter stores it in the environment
- `say` resolves identifiers and displays their value

This is the foundation for future language features without introducing unsupported complexity.

## 10. Summary

The current system supports declaration and printing of literal values only.

Valid examples:

```drift
var age = 20
var pi = 3.1416
var name = "Israfil"
var online = true

say age
say pi
say name
say online
```

This gives Drift a clean, minimal variable system while keeping the language safe and easy to extend later.
