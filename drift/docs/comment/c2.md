# Comment Usage Examples and Best Practices

## Basic Examples

### Single-line Comments

```drift
// Initialize variable
var count = 0

var name = 'Alice'  // Store person's name
say name            // Print the name
```

### Multi-line Comments

```drift
/*
    Configuration section.
    Sets up initial values.
    This entire block is documentation.
*/
var config_value = 100
var threshold = 50
```

### Executable Documentation Blocks

```drift
/*
    This is documentation.

    @exc
        say "I"
        say "hate"
        say "c"
    .exc

    The lines above execute.
    Everything else in this block is documentation.
*/
```

Output:

```text
I
hate
c
```

### Inline Comments

```drift
var score = 95      /* Student test score */
say score           /* Display the score */
```

## Advanced Examples

### Comments with Arrays

```drift
// Initialize array with numbers
var numbers[] = {10, 20, 30, 40, 50}

/* Access and print array elements */
say numbers[0]      // First element
say numbers[4]      // Last element
```

### Comments with Array Selection

```drift
/*
 * Advanced array operations
 * Use select() to filter array values
 */
var data[] = {1, 2, 3, 4, 5}
say data.select((2, 4))  // Select elements at indices 2 and 4
```

### Documentation Comments

```drift
/*
 * Application Entry Point
 * This section initializes all application variables
 * and performs basic setup operations
 */
var app_version = 1
var app_name = 'MyApp'
var debug_mode = true  // Enable debugging

say app_name
```

## Real-World Patterns

### Problem-Solution Pattern

```drift
// Problem: Need to store user information
// Solution: Create variables for each field
var user_id = 12345
var user_name = 'John Doe'
var user_age = 30

// Display user info
say user_name
say user_age
```

### Section Markers

```drift
// ============================================
// INITIALIZATION SECTION
// ============================================

var initialized = true
var setup_complete = false

// ============================================
// MAIN EXECUTION
// ============================================

say initialized
say setup_complete
```

### Temporary Debug Code

```drift
var result = 42

// DEBUG: Print intermediate values
say result          /* TODO: Remove after testing */

var final_output = result
say final_output
```

### Complex Logic Documentation

```drift
/*
 * Matrix initialization
 * Creates a 2D array structure for:
 * - Storing graph data
 * - Mathematical computations
 */
var matrix[] = {
    {1, 2, 3},      // Row 1
    {4, 5, 6},      // Row 2
    {7, 8, 9}       // Row 3
}

say matrix[0]       // Print first row
```

## REPL Interactive Session Example

```
>>> // Start a calculation
>>> var base = 10
>>> 
>>> /*
...  * Multi-line comment in REPL
...  * Notice the "..." prompt continuation
...  */
>>> var multiplier = 5
>>> var result = base * multiplier
Syntax Error: Only literal values are allowed during variable declaration in Drift v0.2.
>>> 
>>> // Just use separate statements
>>> var total = 50
>>> say total
50
>>>
```

## Comments with Different Statement Types

### Print Statements with Comments

```drift
// Simple print
say 'Hello'         // Output text

say 'World'         /* Multi-line
                       comment example */
```

### Variable Declarations with Comments

```drift
// Single integer
var x = 42

```

## Comment Boundaries

### Properly Closed Comments

```drift
var x = 10  /* This comment is closed */
say x
```

### Unterminated Comments (REPL Behavior)

```
>>> var x = 10  /* Open comment
... (REPL waits for closure)
... var y = 20
... */
>>> say x
10
>>>
```

## Things to Avoid

### ❌ Incorrect: Comment syntax inside comments

```drift
// var x = 10  /* nested comment - avoid this */
```

### ❌ Incorrect: Trying to execute commented code

```drift
/*
var secret = 999  // This does NOT execute
*/
// To enable: uncomment the line above
```

### ✓ Correct: Clear comment structure

```drift
// Initialize secret value
var secret = 999

/* 
 * Above value is secret
 * Use carefully
 */
```

## Recommended Style Guidelines

1. **Use `//` for single-line comments** - Cleaner for brief explanations
   
2. **Use `/* */` for documentation** - Better for multi-line explanations

3. **Comment WHY, not WHAT** - Explain the reasoning, not the obvious
   ```drift
   // Bad:
   var x = 5  // Set x to 5
   
   // Good:
   var x = 5  // Timeout interval in seconds
   ```

4. **Keep comments synchronized** - Update comments when code changes

5. **Use consistent formatting** - Align comments for readability
   ```drift
   var name = 'Alice'    // User name
   var age = 25          // User age
   var status = 'Active' // User status
   ```

## Integration with Version Control

When committing code with comments:

```bash
git add .
git commit -m "Add user authentication logic with documentation comments"
```

Comments are helpful for:
- Code reviews (reviewers understand the intent)
- Maintenance (future developers know why code exists)
- Debugging (quickly identify important sections)
